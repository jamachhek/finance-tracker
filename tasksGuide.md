# tasksGuide — как работать с задачами

## 1. Формат задачи в [Tasks.md](Tasks.md)
```
- [ ] T-NN Короткое название — P1, зависит от T-XX
```
- `T-NN` — сквозной номер, не переиспользуется.
- Приоритет: **P1** — нужно для релиза, **P2** — важно, **P3** — когда будет время.
- Когда готово: `[x]`, перенести в «Сделано» и дописать хеш коммита.

## 2. Цикл одной задачи
1. **Понять**: свериться с [PRD.md](PRD.md) (зачем) и [SPEC.md](SPEC.md) (как устроено).
2. **Дизайн**: новые элементы — по [design.md](design.md): токены цветов, стекло, скругления, анимации с учётом `prefers-reduced-motion`.
3. **Сделать**: фронтенд — только `index.html`, `main.css`, `script.js` (без сборки); сервер — `api/*.js`, общие помощники — `api/_lib/`.
4. **Тексты**: каждую новую строку интерфейса добавить в оба языка `I18N.ru` и `I18N.uz`.
5. **Проверить** (см. чек-лист ниже).
6. **Сохранить**: коммит на русском, коротко о сути. Перед отправкой на GitHub — спросить владельца.
7. **Выложить**: `vercel deploy --prod --yes`; если менялась база — сначала `npm run migrate`.

## 3. Чек-лист проверки
- [ ] Работает в светлой и тёмной теме.
- [ ] Работает на RU и UZ, тексты не обрезаются.
- [ ] Телефон (375px) и компьютер; нет горизонтальной прокрутки.
- [ ] Локальный режим (без `/api`) и облачный режим.
- [ ] Старые данные открываются (проверить `normalizeState`).
- [ ] Нет ошибок в консоли браузера.
- [ ] Секреты не попали в код, коммит или вывод.

## 4. Правила
- Не коммитить и не выкладывать папку `physic/`, файлы `.env*`.
- Не показывать ключи (`DATABASE_URL`, `SESSION_SECRET`, `RESEND_API_KEY`) ни в чате, ни в логах.
- Не удалять проекты и данные в Neon/Vercel без согласия владельца.
- Изменение схемы базы — только добавлением (`if not exists`), чтобы миграцию можно было запускать повторно.
